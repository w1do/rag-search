# AGENTS.md — Vector

Правила для AI-агентов, работающих в этом репозитории. Общее описание проекта — в `CLAUDE.md`.

## Проект
База знаний Vector: RAG-сервис для проектов. Модульный монолит, PostgreSQL — источник истины, Qdrant и Typesense — производные индексы.

## Вход и запуск
- Вход по `.env`: `EMAIL=` и `PASSWORD=` — вход в веб-интерфейс/API; `MCP_TOKEN=` — токен агентов для MCP. Значения только из vault, в репозиторий не попадают.
- Запуск одной командой (цель, этап 3): `cp .env.example .env`, заполнить `EMAIL`, `PASSWORD`, `MCP_TOKEN` и `docker compose up -d`. Остальные переменные имеют значения по умолчанию в compose; ручная настройка не требуется.
- AI: `AI_API_KEY` (из vault), `AI_API_BASE` или `AI_BASE_URL` (по умолчанию Polza в `.env.example`), `AI_EMBEDDING_MODEL=openai/text-embedding-3-small`; без ключа работает только полнотекстовый поиск с предупреждением. Смена модели или размерности: удалить коллекцию Qdrant `chunks` и выполнить reindex.
- Статус: `docker-compose.yml` и авторизация по этим переменным реализованы (PLAN.md, этапы 3–4).

## Правила
- Каждый поиск и контекст требуют явный `project_id`; без него — ошибка.
- Без `latest` в зависимостях и образах; версии фиксируются в `pyproject.toml`, `apps/web/package-lock.json` и `docker-compose.yml`.
- Секреты только из vault через MCP. Значения не записывать в код, YAML, `.env.example`, логи и коммиты.
- Без n8n.

## Получение секретов из vault
1. Подключиться к MCP vault.
2. Запросить нужный ключ по имени: `BACKEND_KEY`, `PROJECT_IT`, ключ AI-провайдера (`AI_API_KEY`).
3. Использовать значение только в окружении процесса. Не сохранять в файлы и не выводить в ответ.
4. Если vault недоступен — остановиться и сообщить о блокировке. Не подставлять значения из локальных файлов.

## Память проекта
- Перед чтением кода использовать индекс `memory`.
- После добавления, изменения или удаления файла: `memory_update` или `memory sync`.

## Синхронизация документов
После каждого завершённого этапа обновить `PLAN.md` и `GOAL.md`, затем синхронизировать память проекта. Документы описывают только факты, подтверждённые проверками.

## Оркестрация агентов
- Главный агент (`claude-fable-5-1`) — оркестратор. Он единственный общается с пользователем.
- Оркестратор не пишет, не редактирует и не исправляет код, тесты, конфиги и документацию сам, и не выполняет задачи сам (исследование, реализация, ревью, документация).
- Оркестратор следит за выполнением, делегирует работу суб-агентам, проверяет их результаты и присылает пользователю только отчёты: статус, проверенные результаты, блокеры и вопросы. Сырой вывод суб-агентов и черновики кода пользователю не отправляются.
- Реализацию выполняют суб-агенты (`developer` и др.).
