## Why

Если добавить источник по ссылке, его данные в базе знаний выглядят обрезанными. Сейчас `fetch_url` делает обычный `GET` без рендера JavaScript, а `_HtmlTextParser` склеивает весь текст страницы в одну строку. Он удаляет только `script` и `style`, а навигацию, меню и футеры оставляет. Поэтому на SPA и динамических страницах извлекается только часть контента, а структура (заголовки, списки, таблицы) пропадает. Чтобы получать полный и чистый текст страницы, ссылки нужно извлекать через Firecrawl (`POST /v2/scrape`, формат `markdown`). Firecrawl рендерит JS и обходит anti-bot.

## What Changes

- Ссылки (`POST /api/projects/{id}/sources/url`) извлекаются через Firecrawl Scrape API, если в окружении задан `FIRECRAWL_API_KEY`. Результат — полный Markdown основного контента страницы (`onlyMainContent: true`).
- Markdown сохраняется как версия источника с расширением `md` и индексируется существующим пайплайном: чанки, Typesense, Qdrant. Текст не усекается, единственное ограничение — общий лимит `MAX_UPLOAD_BYTES`.
- Заголовок источника по умолчанию берётся из `metadata.title` страницы. Сейчас он берётся из последнего сегмента пути URL.
- Ошибки Firecrawl превращаются в понятные сообщения: нет кредитов (`402`), лимит запросов (`429`), таймаут, недоступная страница, пустой результат. Источник в этих случаях получает статус `failed` с этим сообщением. Тихого отката на встроенный загрузчик нет: иначе снова получится обрезанный текст.
- Без `FIRECRAWL_API_KEY` ссылки по-прежнему загружает встроенный загрузчик. Запуск одной командой работает без новых обязательных переменных.
- Новые настройки: `FIRECRAWL_API_KEY` (секрет, из vault), `FIRECRAWL_BASE_URL` (по умолчанию `https://api.firecrawl.dev`), `FIRECRAWL_TIMEOUT_SECONDS` (по умолчанию `60`). Ключ не попадает в логи, `repr`, ответы API и в репозиторий.
- Новых зависимостей нет: клиент пишется на уже закреплённом `httpx==0.28.1`.

## Capabilities

### New Capabilities
- `link-extraction`: извлечение содержимого веб-страниц по ссылке через внешний сервис Firecrawl. Включает выбор загрузчика по конфигурации, формат результата, заголовок, обработку ошибок и защиту ключа.

### Modified Capabilities
- `vector-kb`: меняется требование «Knowledge sources», сценарии «Add link» и «Unreachable link». Источник-ссылка индексируется по полному извлечённому содержимому страницы, а не по сырому тексту HTML.

## Impact

- Код: `packages/core/vector_core/extract.py` (новый `FirecrawlFetcher` рядом с `fetch_url`), `packages/core/vector_core/services/sources.py` (`add_url`, `_fetch_url_version`), `packages/core/vector_core/config.py` (новые поля `Settings`), `apps/api/app/deps.py` (сборка загрузчика).
- Инфраструктура: `docker-compose.yml` (проброс `FIRECRAWL_*` в `api` и `worker`), `.env.example` (пустой `FIRECRAWL_API_KEY=`).
- API: контракт `POST /sources/url` не меняется. Меняются только содержимое версии (`md`) и заголовок по умолчанию.
- Внешняя система: Firecrawl Cloud (`api.firecrawl.dev`). URL страниц уходит третьей стороне, вызовы расходуют кредиты аккаунта.
- Существующие URL-источники автоматически не перекачиваются. Чтобы получить полный текст, источник нужно удалить и добавить заново.
- Тесты: `tests/test_extract.py`, `tests/test_sources.py`, все на `httpx.MockTransport`, без реальных вызовов Firecrawl.
