# CLAUDE.md — Vector

## Что за проект
Vector — самостоятельный сервис единой базы знаний по проектам. Хранит сведения о проектах, услуги и цены, документы, ссылки, заметки и голос. Знания отдаются AI-ассистентам через API, MCP и CLI по схеме RAG.

## Стек и границы
- Монорепо: `apps/api` (FastAPI), `apps/worker`, `apps/web` (React, Vite, shadcn/ui, Tailwind CSS 4), `packages/core` (SQLAlchemy 2, Pydantic 2, Alembic), `packages/cli` (Typer, команда `vector`).
- Модульный монолит, один backend-образ для `api` и `worker`.
- PostgreSQL — источник истины. Qdrant и Typesense — производные индексы, восстанавливаемые из PostgreSQL.

## Вход и запуск
- Вход по `.env`: `EMAIL=` и `PASSWORD=` — вход в веб-интерфейс/API; `MCP_TOKEN=` — токен агентов для MCP. Значения только из vault, в репозиторий не попадают.
- Запуск одной командой (цель, этап 3): `cp .env.example .env`, заполнить `EMAIL`, `PASSWORD`, `MCP_TOKEN` и `docker compose up -d`. Остальные переменные имеют значения по умолчанию в compose; ручная настройка не требуется.
- Статус: `docker-compose.yml` и авторизация по этим переменным ещё не реализованы (PLAN.md, этапы 3–4).

## Правила
- Отсутствие `project_id` в запросе — ошибка, а не поиск по всей базе.
- Версии зависимостей и образов фиксированы; `latest` не используется.
- Секреты только из vault через MCP; значения не пишутся в репозиторий, логи и коммиты.
- Не использовать n8n и дополнительные оркестраторы.

## Vault и память проекта
- Ключи и креды (`BACKEND_KEY`, `PROJECT_IT`, ключи AI-провайдера) получать через MCP vault. Значения в файлы не записывать.
  - Память проекта: `memory` (MCP и CLI). После изменения файлов выполнять `memory sync` или `memory_update` и `memory_annotate`

## Синхронизация документов
- После каждого завершённого этапа обновлять `PLAN.md` и `GOAL.md`, затем синхронизировать память проекта.
