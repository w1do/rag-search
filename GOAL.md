# GOAL.md — Vector

Цель: первая версия Vector по ТЗ. Отметки `[x]` ставятся только после проверки.

## Критерии приёмки (ТЗ, раздел 20)

- [ ] 1. Созданы два проекта; поиск и API-ключ первого не получают данные второго.
- [ ] 2. Загружены PDF, DOCX, текст, ссылка; сохранены оригиналы и извлечённое содержание.
- [ ] 3. Голос превращается в редактируемую заметку и сохраняется после подтверждения.
- [ ] 4. Повторный `vector sync` не создаёт дубли.
- [ ] 5. Изменённый файл создаёт новую версию.
- [ ] 6. Ошибка обновления не уничтожает предыдущую опубликованную версию.
- [ ] 7. Удалённый источник сразу исчезает из поиска и контекста.
- [ ] 8. `vector sync ./folder` обрабатывает локальный каталог с исключениями.
- [ ] 9. `--prune` не затрагивает материалы вне своей привязки.
- [ ] 10. MCP выполняет реальный поиск и добавление заметки из выбранного клиента.
- [ ] 11. Внешнее приложение получает ответ с источниками.
- [ ] 12. При недоступности эмбеддингов работает полнотекстовый поиск с предупреждением.
- [ ] 13. Старый прайс не подменяет действующую подтверждённую цену.
- [ ] 14. При отсутствии цены система сообщает об отсутствии данных.
- [ ] 15. При конфликте сведений возвращается предупреждение.
- [ ] 16. Перезапуск worker не теряет задачи.
- [ ] 17. Индексы пересобираются из PostgreSQL и файлов.
- [ ] 18. Резервная копия восстанавливается на чистом окружении.
- [ ] 19. Сервис запускается одной командой (`docker compose up -d`) после заполнения `.env` (`EMAIL`, `PASSWORD`, `MCP_TOKEN`).
- [ ] 20. Отзыв ключа немедленно прекращает доступ.
