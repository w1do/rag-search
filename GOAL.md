# GOAL.md — Vector

Цель: первая версия Vector по ТЗ. Отметки `[x]` ставятся только после проверки.

## Критерии приёмки (ТЗ, раздел 20)

- [x] 1. Созданы два проекта; поиск и API-ключ первого не получают данные второго. Примечание: изоляция по API-ключу проверена (этап 4: ключ проекта A на `/B` → 403); изоляция поиска проверена PG-тестом `test_search_is_isolated_between_projects_with_postgres` (этап 7).
- [x] 2. Загружены PDF, DOCX, текст, ссылка; сохранены оригиналы и извлечённое содержание. Примечание: приём `.txt/.md/.pdf/.docx`, текста и ссылки через `/api/projects/{id}/sources/*`; оригинал в blob-хранилище и извлечённый текст в `source_versions` подтверждены unit- и PostgreSQL-тестами (этап 6a); PDF и DOCX загружены через `vector sync`, ссылка через `POST /sources/url`: все три проиндексированы (`indexed`, `published`, `vector_indexed=true`) и найдены через `/api/v1/search` по своим маркерам первыми, `warning: null` (финализация, live smoke).
- [ ] 3. Голос превращается в редактируемую заметку и сохраняется после подтверждения. Примечание: не в этой версии.
- [x] 4. Повторный `vector sync` не создаёт дубли. Примечание: на стенде повторный `sync` → uploaded=0 (этап 7a); тест `test_repeated_sync_uploads_nothing_and_keeps_source_count` в `test_cli_sync.py`.
- [x] 5. Изменённый файл создаёт новую версию. Примечание: на стенде изменение файла → uploaded=1, версия 2 (этап 7a).
- [ ] 6. Ошибка обновления не уничтожает предыдущую опубликованную версию. Примечание: предыдущая версия удаляется из PG и индексов только после commit новой версии (этап 6b); сценарий «ошибка обновления → предыдущая опубликованная версия остаётся доступной в поиске» не проверялся, поэтому пункт не отмечен.
- [x] 7. Удалённый источник сразу исчезает из поиска и контекста. Примечание: удаление PDF, DOCX и ссылки на стенде → хиты исчезли из `/api/v1/search` и `/api/v1/context` (финализация, live smoke); удаление из индексов реализовано в этапе 6b (`SourceService.delete`, job `purge_source`).
- [x] 8. `vector sync ./folder` обрабатывает локальный каталог с исключениями. Примечание: тест `test_exclude_patterns_skip_matching_files` в `test_cli_sync.py`; на стенде `sync` каталога → uploaded=3 (этап 7a).
- [x] 9. `--prune` не затрагивает материалы вне своей привязки. Примечание: тест `test_prune_removes_only_missing_file_of_its_root` в `test_cli_sync.py`; prune выбирает источники только по `sync_root`; на стенде удаление + `--prune` → pruned=1 (этап 7a).
- [ ] 10. MCP выполняет реальный поиск и добавление заметки из выбранного клиента. Примечание: `search` и `add_note` через `/mcp` проверены живьём по HTTP curl-клиентом (этап 7; финализация: `tools/list` = `search`, `context`, `add_note`, `add_note` → indexed); формулировка требует конкретного выбранного клиента, его проверки нет, поэтому пункт не отмечен.
- [x] 11. Внешнее приложение получает ответ с источниками. Примечание: `POST /api/v1/context` с ключом проекта → 200, в ответе `sources` (тест `test_context_respects_budget_and_lists_each_source_once`, этап 7).
- [x] 12. При недоступности эмбеддингов работает полнотекстовый поиск с предупреждением. Примечание: тесты `test_search.py` проверяют warning `vector_search_unavailable` и текстовые результаты (этап 7); отказ реальных эмбеддингов на стенде не воспроизводился.
- [ ] 13. Старый прайс не подменяет действующую подтверждённую цену. Примечание: не в этой версии.
- [ ] 14. При отсутствии цены система сообщает об отсутствии данных. Примечание: не в этой версии.
- [ ] 15. При конфликте сведений возвращается предупреждение. Примечание: не в этой версии.
- [x] 16. Перезапуск worker не теряет задачи.
- [ ] 17. Индексы пересобираются из PostgreSQL и файлов. Примечание: `reindex_project` пересобирает индексы из опубликованных чанков PostgreSQL (тест `test_reindex_project_restores_lost_documents` в `test_indexing.py`; на стенде `vector reindex` → job `reindex_project` succeeded), но не читает файлы из blob-хранилища; пересборка из файлов не подтверждена, поэтому пункт не отмечен.
- [ ] 18. Резервная копия восстанавливается на чистом окружении. Примечание: не в этой версии.
- [x] 19. Сервис запускается одной командой (`docker compose up -d`) после заполнения `.env` (`EMAIL`, `PASSWORD`, `MCP_TOKEN`).
- [x] 20. Отзыв ключа немедленно прекращает доступ.
